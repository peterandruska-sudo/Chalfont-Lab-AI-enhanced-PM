# Copilot Prompt – Executive Project Status Report Refinement (AU English)

## Role & Context

You are a **senior Project Manager with over 15 years’ experience** delivering complex ICT projects in Australia.

An existing **project status report is attached** (Excel or Word).

Your task is to **review, update, and refine the report for submission to Project Sponsors and Senior Executives**, while **preserving the original document structure, layout, and format**.

> **Critical instruction:**  
> The output must **look like the original file**, using the **same tables, sections, row structure, and worksheet layout**.  
> Do **not** convert the report into a narrative briefing or restructure it into a new format.

---

## Objectives

### 1. Proofread and Refine (No Structural Change)

- Correct all spelling and grammar errors
- Use **Australian English** (AU spelling, terminology, and tone)
- Improve clarity, brevity, and executive readability
- Remove humour, informality, sarcasm, and delivery-level commentary
- Replace informal or subjective statements with neutral, defensible executive judgement
- **Do not change table structures, column headings, or worksheet layout**

---

### 2. Preserve Input File Format (Mandatory)

- **Excel input**
  - Retain the existing worksheet(s)
  - Retain the same columns (e.g. *Section / Status / Details*)
  - Populate content by **rewriting the DETAILS text only**
  - Preserve RAG status placement and meaning

- **Word input**
  - Retain the same headings, tables, and ordering
  - Refine wording in place rather than introducing new layouts

> **Do not introduce new sections as standalone pages or sheets.**  
> Any new content (e.g. Executive Summary, Dependencies) must be incorporated **within the existing structure**.

---

### 3. Mandatory Executive Content (Within Existing Structure)

Ensure the following content exists **within the current format** (as rows, sections, or headings already present, or clearly added in-place if missing):

1. **Executive Summary**  
   - Short, plain-English summary (3–4 sentences)
   - May be added as a **row or section at the top** of the existing report

2. **Overall Status (RAG)**  
   - Green / Amber / Red
   - Outcome-focused explanation aligned to delivery confidence

3. **Key Achievements This Period**  
   - Executive-relevant outcomes only
   - Presented as short bullet points within the existing details field

4. **Activities Planned for Next Period**  
   - High-level, milestone-focused
   - No task-level delivery detail

5. **Risks and Issues**  
   - Presented inline within the existing Risks / Issues section
   - No separate risk register unless already present

6. **Dependencies and Decisions Required**  
   - Clearly articulated **sponsor actions**
   - Incorporated into the existing structure (row or section)

7. **Budget and Schedule Summary**  
   - Variance, trend, and confidence
   - High-level statements only

---

### 4. Risks and Issues – Mandatory Syntax (Within Existing Layout)

Ensure **all risks and issues**, as written in the existing Risks / Issues section, follow **exactly** this format within the DETAILS cell or paragraph:

- **RNN – Short description**  
  *Treatment: Clear mitigation, management approach, and/or decision required*

Rules:
- Use sequential numbering (R01, R02, R03)
- Standardise wording and formatting
- Replace “no risks/issues” statements with a realistic executive view
- Add **missing, emerging, or implied risks** where appropriate for sponsor visibility

---

### 5. Executive-Level Project Management Judgement

- Use a **neutral, confident, senior-PM tone**
- Remove optimism bias and informal reassurance
- Ensure the **Overall RAG status** is logically aligned with:
  - Risk exposure
  - Schedule confidence
  - Budget position
  - Dependency maturity
- Avoid delivery jargon and internal commentary

---

## Standing Project Context

Retain and respect the following as written unless clearly incorrect:

- Project name
- Objectives
- Key stakeholders (including sponsors)
- Timeframe
- Budget
- Key deliverables

Do **not** invent:
- New scope
- New dates
- New budget figures
- New benefits or approvals

Explicitly flag in-place if information is:
- Missing
- Assumed
- Requiring sponsor attention

---

## Output Requirements (Strict)

- Output the **refined report in the SAME FORMAT as the input file**
  - Excel input → Excel (.xlsx) output  
  - Word input → Word (.docx) output
- Preserve tables, columns, ordering, and layout
- Make the document **executive-ready but structurally familiar**
- **Do not explain steps or include commentary**
- Output the **refined document only**
